Claude Code で Claude Opus 5.5 を使うときは、ユーザー設定の古いキーが Opus 5.5 に効かない点に注意が要ります。ユーザー設定の最上位に `effortLevel` を書いただけだと、Opus 5.5 は既定の medium のまま動きます。以下、手を動かす順に説明します。

## Claude Code で Opus 5.5 に切り替えるには？ (/model・--model・設定の model)

やり方は 3 つあり、どこまで効かせたいかで使い分けます。今のセッション中なら `/model`、起動するときなら `--model`、ずっと使うなら設定ファイルの `model` です。

手元ですぐ試せるのは、セッション中に引数を付けずに `/model` だけを打ち、開いたピッカーから Opus 5.5 を選ぶ方法です。

```text
/model
```

名前で直接切り替えるときは、`/model` の後ろにエイリアスかモデル名を続けると、その場で切り替わります。起動するときに決めるなら、`claude` を起動するときに `--model` でエイリアスかモデル名を渡します。

ピッカーで `s` を押す場合を分けると、次の 4 通りです。それぞれ効く範囲が違います。

| 方法 | 効く範囲 | 補足 |
| --- | --- | --- |
| `/model` に名前を付ける／ピッカーで選ぶ | 今のセッションと、以後の新しいセッションの既定 | すぐに切り替わる。選んだモデルはユーザー設定の `model` に書き込まれる |
| `/model` のピッカーで `s` を押す | このセッションだけ | 既定は変わらない |
| `claude --model`・環境変数 `ANTHROPIC_MODEL` | それで起動したセッションだけ | 既定は変わらない |
| 設定ファイルの `model` | ずっと | プロジェクトの設定と管理の設定が優先され、次の起動でまた適用される |

`/model` で選んだモデルはユーザー設定の `model` に書かれますが、プロジェクトの設定や管理の設定のほうが優先されます。それらに `model` が書かれていれば、次の起動ではそちらがまた使われます。「試しに 1 回だけ使いたい」なら、ピッカーで `s` を押すか、`--model` で起動するのが安全です。

## effort の段階はどこで設定する？ (/effort・--effort・環境変数・modelSettings)

設定できる場所は 4 つです。セッション中の `/effort`、起動時の `--effort`、環境変数 `CLAUDE_CODE_EFFORT_LEVEL`、設定ファイルの `modelSettings`・`effortLevel` です。Opus 5.5 で選べる段階は low・medium・high・xhigh・max の 5 つです。

**セッション中 (`/effort`)**

- `/effort` の後ろに段階の名前を書くと、その段階が設定され、既定としても保存されます。
- 引数を付けずに `/effort` だけを打つと、スライダーが開きます。
- スライダーや `/model` のピッカーで `s` を押すと、その段階がこのセッションだけに効きます (Claude Code v2.1.257 以降)。
- 今のモデルに保存した段階を消すには、`auto` を指定します。

たとえば high に設定して既定として保存するには、次のように打ちます。

```text
/effort high
```

保存した段階を消すときは、次のように打ちます。

```text
/effort auto
```

**起動時 (`--effort`)**

`--effort` に段階の名前を渡すと、その起動で始まった 1 つのセッションにだけ効きます。

```bash
claude --effort high
```

**環境変数 (`CLAUDE_CODE_EFFORT_LEVEL`)**

段階の名前か `auto` を入れます。`max` は、この環境変数で設定したとき以外は今のセッションだけに効きます。

この起動に `max` を渡す例です。

```bash
CLAUDE_CODE_EFFORT_LEVEL=max claude
```

**設定ファイル (`modelSettings`・`effortLevel`)**

- `modelSettings` には、モデルごとの段階を書きます。
- `effortLevel` には、段階を保存していないモデルに使う既定を書きます。

次の表で比べます。

| 方法 | 保存されるか | `max` を指定したとき | 補足 |
| --- | --- | --- | --- |
| `/effort` に段階の名前を付ける | 既定として保存される | 今のセッションだけに効く | ─ |
| スライダー・ピッカーで `s` | 保存されない (このセッションだけ) | ─ | Claude Code v2.1.257 以降 |
| `--effort` | 保存されない (起動した 1 つのセッションだけ) | 今のセッションだけに効く | ─ |
| `CLAUDE_CODE_EFFORT_LEVEL` | 保存はしないが、明示の指定として効く (保存した設定より優先) | 今のセッションだけに限られない | 値は段階の名前か `auto` |
| `modelSettings`・`effortLevel` | 保存した設定として効く | 書けない | ─ |

## effort はどの順で決まる？ 既定の medium になるのはどんなとき？

effort は、優先度の高い順に次の 3 つを見て決まります。上で決まれば、下は見ません。

```text
明示の指定 (環境変数・起動時のフラグ・/effort)
  ↓
保存した設定 (modelSettings・effortLevel)
  ↓
モデルの既定 (Opus 5.5 は medium)
```

- **明示の指定**: 環境変数 `CLAUDE_CODE_EFFORT_LEVEL`、起動時の `--effort`、セッション中の `/effort`
- **保存した設定**: モデルごとに保存した段階 (`modelSettings`)、または `effortLevel` のキー
- **モデルの既定**: Opus 5.5 は `medium`

つまり、Opus 5.5 が既定の medium で動くのは、明示の指定も、Opus 5.5 に効く保存した設定も無いときです。「設定したのに medium のまま」というときは、書いた設定が本当に Opus 5.5 に効く場所にあるかを確かめてください。注意が要るのが、次の節で扱うユーザー設定の `effortLevel` です。

:::message
API では、Opus 5.5 に `medium` を明示した要求と、effort を省いた要求は同じように動きます。medium を使うだけなら、明示しなくても同じ動作になります。
:::

## ユーザー設定の effortLevel が Opus 5.5 に効かないのはなぜ？

ユーザー設定の最上位にある `effortLevel` は、Opus 5.5 には効かない古い形のキーだからです。これしか書いていない場合、Opus 5.5 は明示の指定も保存した設定も無いものとして扱われ、既定の medium から始まります。

ただし、`effortLevel` がどこでも効かないわけではありません。次の場所に書いた `effortLevel` は、Opus 5.5 を含むすべてのモデルに効きます。

| `effortLevel` を書いた場所 | Opus 5.5 に効くか |
| --- | --- |
| ユーザー設定の最上位 | 効かない (古い形のキー) |
| プロジェクトの設定の最上位 | 効く |
| ローカルの設定の最上位 | 効く |
| 管理の設定の最上位 | 効く |
| `--settings` で渡した設定 | 効く |

自分の環境で Opus 5.5 の段階を保存しておきたいときは、次のどれかを使います。

1. セッション中に `/effort high` のように段階の名前を付けて打つ (設定して、既定として保存されます)。
2. プロジェクト・ローカル・管理の設定、または `--settings` で渡す設定に `effortLevel` を書く。モデルごとに段階を分けたいときは、`modelSettings` にモデルごとの段階を書く (`max` は書けません)。
3. 保存した設定より優先させたいなら、環境変数 `CLAUDE_CODE_EFFORT_LEVEL` を使う (明示の指定です)。

## -p の非対話モードでは設定がどう扱われる？

`-p` の非対話モードでは、`/model` も `/effort` もそのセッションだけに効き、既定には保存されません。`-p` の中で `/model` を使うには、Claude Code v2.1.205 以降が必要です。

なお、起動時の `--model`・環境変数 `ANTHROPIC_MODEL`・`--effort` は、それで起動したセッションに効きます (最初の 2 つの節で説明したとおりです)。

## API・Bedrock ではモデル ID をどう指定する？

Claude API ではモデル ID に `claude-opus-5-5` を、Amazon Bedrock では `anthropic.claude-opus-5-5` を指定します。

| 使う場所 | モデル ID |
| --- | --- |
| Claude API | `claude-opus-5-5` |
| Amazon Bedrock | `anthropic.claude-opus-5-5` |

```json
{
  "model": "claude-opus-5-5"
}
```

API で気をつける点は 3 つです。

- Opus 5.5 では、適応的な思考が常に有効で、切ることはできません。思考の深さは effort で調整します。
- 思考を切る要求 (`thinking: {"type": "disabled"}`) を送ると、effort がどの段階でも 400 エラーが返ります。
- 高い段階の effort を使うときは `max_tokens` を大きく取ります。`max_tokens` は、思考と応答を合わせた量の上限になるためです。

## Opus 5 のコードを Opus 5.5 に移すと、どこで壊れる？

モデル ID を書き換えるだけでは、止まる所と、エラーにならずに動きが変わる所があります。まず、Opus 5 向けに書いたコードがそのままでは動かなくなる変更です。移す前に、Opus 5 向けのコードで次の点を確かめてください。

- **思考を切る設定を送っていないか**: `thinking: {"type": "disabled"}` を含む要求は、Opus 5.5 では 400 エラーになります。
- **ツールの使用を強制していないか**: Opus 5.5 では、強制するとエラーになります。
- **`computer_20251124` のツールを使っていないか**: Claude API と Google Cloud では、この以前のツールを受け付けません。
- **思考のブロック**: 思考のブロックがモデルと会話に結びつくことも、破壊的な変更として挙げられています。

エラーにはならないのに、動きが変わる所もあります。

- **既定の effort が下がる**: Opus 5 の既定は `high` でした。effort を省いた要求は、Opus 5.5 では 1 段低い `medium` で動きます。Opus 5 で使っていた段階をそのまま持ち込まず、自分の評価で段階を試し直すことが勧められています。Claude Code の Model configuration のページも `medium` から始めるよう勧めています。同じ段階なら、Opus 5.5 は Opus 5 より 1 ターンあたりの思考が多くなる傾向があるとも書かれています。
- **ツール呼び出しの間のテキストが空になる**: 表示の設定が既定のままだと、ツール呼び出しの間のテキストは、本文が空の思考のブロックとして返ります。要求は失敗しません。ツール呼び出しの合間に途中経過を表示するアプリでは、表示の設定をテキストを返す値に変えます。

:::message alert
「エラーが出ないから移行できた」とは限りません。既定の effort が high から medium に下がることと、ツール呼び出しの間のテキストが空で返ることは、どちらもエラーにならずに起きます。移したあとは、要求の effort と表示の設定を確かめてください。
:::

## 設定が効かないときは何を確かめる？

次の順に確かめると、どこで食い違っているかを絞り込めます。

- **ユーザー設定**: 最上位に `effortLevel` だけを書いていないか。書いていれば、`/effort high` のように段階の名前を付けて打ち、段階を保存し直します。
- **プロジェクト・管理の設定**: `model` が書かれていないか。書かれていると、`/model` で選んだモデルより優先され、次の起動でまた適用されます。
- **環境変数と起動のコマンド**: `CLAUDE_CODE_EFFORT_LEVEL` が設定されたままになっていないか。起動のコマンドやスクリプトに `--effort`・`--model` を付けていないか。`CLAUDE_CODE_EFFORT_LEVEL` と `--effort` は明示の指定なので、保存した設定より優先されます。
- **`-p` の実行**: 前の実行の `/model`・`/effort` が残る前提になっていないか。
- **API の要求**: モデル ID が `claude-opus-5-5` (Bedrock は `anthropic.claude-opus-5-5`) か。effort を省いていないか、思考を切る設定・ツールの使用の強制・`computer_20251124` が残っていないか。
