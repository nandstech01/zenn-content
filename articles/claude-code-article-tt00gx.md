## はじめに

Claude Code を使い込んでいくと、ある時点でコストの不透明感に悩み始める。自分もそのひとりで、「なんとなく高い気がする」から「なぜ高いのかを構造で理解する」に移行したことで、請求を半分以下に抑えられた。

この記事では、コスト削減の"気合論"ではなく、**トークン消費の仕組みを起点にした実装レベルの対策**を書く。自社ブログにもっと詳しい実装手順を書いているので、後で参照してほしい。

---

## コスト構造を式で理解する

まず前提として、Claude Code の API コストは以下の式で動いている。

```
月コスト ≈ Σ (input_tokens_i + output_tokens_i) × price_per_token
```

ここで見落としがちなのが `input_tokens_i` の中身だ。1 回の「ちょっと直して」という発言が、実際には以下を全部含んでいる：

```
input_tokens = 
  会話履歴の累計
  + 現在読み込まれているファイル群
  + ツール実行の返戻値
  + あなたの1行メッセージ
```

つまり**長い会話セッションでの「軽い一言」が、ものすごく高くつく**。これを理解してから対策を考えると、打ち手が見えやすくなる。

---

## 対策1: コンテキストのライフサイクルを設計する

「なんとなく長く続けてしまう」のが一番の浪費源だ。タスク単位でセッションを切る習慣が最も効く。

```bash
# タスク完了のたびに履歴を切る
/clear

# 誤ってクリアしても戻れる（v2.1.191+）
/rewind
```

セッションを切るタイミングの判断基準として、自分はこれを使っている：

- 実装フェーズから別のモジュールに移るとき
- 「さっき話した〇〇の話に戻るけど」と言いそうになったとき
- grep や glob の出力が大量に積み上がったとき

大事なのは「消すのが惜しい」という感覚を持たないことで、`/rewind` があれば戻れるので気軽に切れる。

---

## 対策2: 読み込みスコープを `.claudeignore` で絞る

Claude Code がプロジェクトを走査するとき、対象を絞らないと想定外のトークンが積み上がる。`.gitignore` と同じ書式で `.claudeignore` を作るだけで、入力トークンをかなり減らせる。

```
# .claudeignore
node_modules/
dist/
.next/
*.lock
coverage/
*.generated.ts
prisma/generated/
__generated__/
*.png
*.svg
*.jpg
```

特に「自動生成ファイル」と「バイナリ」は最優先で除外すること。大型 Next.js プロジェクトだと、これだけで入力トークンが体感 30〜40% 減ることがある。

加えて、プロンプトで対象を明示する習慣も効く：

```
# 悪い例
認証の不具合を直して

# 良い例
lib/auth/session.ts と app/api/login/route.ts だけ見て、
セッション切れ時の挙動を修正して
```

「全部渡せば安心」は逆に高くつく。

## 対策3: モデルをタスク種別で切り替える

設計・デバッグ・実装・補完でモデルを使い分けると、品質を落とさずコストを大幅に削れる。

| フェーズ | モデル | 理由 |
|---------|--------|------|
| アーキテクチャ検討・根本原因調査 | claude-opus-4-7 | 多段推論が必要 |
| 実装・テスト生成 | claude-sonnet-4-6 | コーディング精度が高い |
| 定型補完・ドキュメント整形 | claude-haiku-4-5-20251001 | Sonnet の 90% 程度の精度でコスト大幅減 |

```bash
# セッション中にその場で切り替える
/model claude-haiku-4-5-20251001

# 設計議論が終わったら即降格
/model claude-haiku-4-5-20251001
```

自分の運用だと「設計の言語化が終わったら Haiku に切って実装する」をデフォルトにしている。Haiku で詰まったら Opus に戻す。この往復で品質を担保しながらコストを抑えられる。

## 対策4: 調査系はサブエージェントに逃がしてコンテキストを汚さない

grep や複数ファイル横断の読み込みをメイン会話でやると、その出力がそのままコンテキストに積み上がる。サブエージェントを使えば、**調査の中間出力はメインに流れてこない**。

```typescript
// 調査はサブエージェントへ
Agent({
  subagent_type: "Explore",
  description: "fetch 呼び出し箇所の調査",
  prompt: `lib/ 以下で fetch または axios を使っている箇所を列挙してください。
  ファイルパスと行番号のみ、箇条書きで最大 10 件。`
})
```

重要なのは**返答を短く指定すること**。詳細を返させすぎると要約がそのままメインに積まれてしまう。「最大 N 件」「N 文字以内」を書く癖をつける。

独立した調査は並列で投げられる。セキュリティチェック・型確認・ドキュメント調査を同時に走らせても、それぞれの内部ログはメインに混入しない。

## 対策5: `CLAUDE.md` で往復コストを事前償却する

毎回「TypeScript strict mode で書いて」「app/ 以下は触るな」「テストは Vitest で」と説明するのは、見えにくいトークン浪費だ。

プロジェクトルートに `.claude/CLAUDE.md` を作ると、セッション開始時に自動で読み込まれる。

```bash
# 雛形を自動生成
/init
```

生成された雛形に以下を追記していく：

```markdown
## 変更禁止
- `app/` 以下のページコンポーネント
- `lib/supabase/` 配下（スキーマ変更はマイグレーション経由）
- `.env.local`（秘密鍵はいかなる出力にも含めない）

## コーディング規約
- TypeScript strict mode 必須
- イミュータブルパターン（ミューテーション禁止）
- テスト: Vitest、カバレッジ 80% 以上
- コメント: WHY が自明でない場合のみ 1 行

## 自律で動いてよい範囲
- lib/cortex/ 以下のファイル編集
- git commit, gh pr create
- Supabase クエリの実行
```

「禁止事項」と「自律で動いていい範囲」を両方書くのがポイント。禁止だけ書くと過剰確認が増えて往復コストが増える。

## 対策6: サブスク枠と API 従量課金の分業を設計する

日常のインタラクティブ作業はサブスク枠で、バッチ処理や自動化スクリプトは API 従量課金枠で——この切り分けが月末請求を安定させる。

```bash
# サブスク枠を使う（CLI 経由のセッション）
claude

# API 枠を使う（スクリプトからの呼び出し）
# ANTHROPIC_API_KEY を直接使う実装のみ
```

注意が必要なのは `claude -p`（`--print` モード）を自動化パイプラインに流用するケース。これはサブスク枠を消費するので、大量実行するなら SDK を直接使う実装に切り出すべきだ。

消費を確認するには：

```bash
# セッション中に確認
/usage
```

Anthropic Console の「Usage」タブで月次推移を見て、週1回ペースでパターンを確認する習慣があると、請求月末サプライズがなくなる。

---

## 対策7: 枠消費のパターンを記録してスケジューリングする

Claude Code Pro/Max の 5 時間ローリングウィンドウは、「最後に API を叩いた時刻」を起点にリセットされる。固定時刻のリセットではないため、重い作業のタイミングで枠が詰まりやすいパターンがある。

自分が試して効いたのは：

1. **重い実装は午前中の早い時間に集中させる**
2. **枠警告が出たら LLM 不要な作業（ドキュメント読み、設計メモ）に切り替える**
3. **ブロックされた時刻を���モして翌週の計画に反映する**

単純だが、「今日の上限がどれくらい残っているか」を意識しながら作業順序を決めるだけで、「油が乗ってきたところでブロック」という最悪パターンを避けられる。

## まとめ

コスト削減のポイントを整理すると：

| 対策 | 効果 | 難易度 |
|------|------|--------|
| `/clear` をタスク単位で打つ | 大 | 低 |
| `.claudeignore` を作る | 大 | 低 |
| モデルをフェーズで使い分ける | 大 | 中 |
| 調査をサブエージェントに逃がす | 中 | 中 |
| `CLAUDE.md` で往復を削る | 中 | 低 |
| 枠と API の分業を設計する | 中 | 中 |
| 作業スケジューリングを最適化する | 小〜中 | 低 |

難易度が低いものから順に試してみてほしい。特に `.claudeignore` と `/clear` 習慣は今日から始められて、来月の請求で体感できる変化がある。
